Roles & Permissions
Admin
•	Full access to all pages and data
•	Create and delete staff accounts
•	View all reports and analytics
•	Manage inventory, donors, patients, requests
Staff / Technician
•	Register new donors
•	Record donations and enter test results
•	Manage blood requests (approve/reject/fulfill)
•	Cannot access admin settings or reports
Donor
•	View own profile and donation history
•	Download donation certificate (PDF)
•	See next eligible donation date
Patient
•	Submit blood requests
•	Track own request status
•	Cannot see other patients' data

Database Tables (Supabase)
Table	Key Columns
users	id, name, email, role, phone, created_at
donors	id, user_id, blood_type, age, weight, last_donation, next_eligible_date, is_eligible
donations	id, donor_id, date, blood_type, units, test_status, notes
blood_inventory	id, blood_type, units, collection_date, expiry_date, status
patients	id, user_id, blood_type, medical_condition
blood_requests	id, patient_id, blood_type, units, urgency, condition, required_date, status, rejection_reason
staff	id, user_id, department, shift
notifications	id, user_id, message, is_read, created_at

RLS Policies
•	donors — can only read/edit their own row
•	patients — can only read/edit their own row
•	staff — read access to donors, donations, requests
•	admin — full access to all tables

API Response Format (All Endpoints)
Success
{ "success": true, "message": "Done", "data": { ... } }
Success with Pagination
{ "success": true, "data": [...],
  "pagination": { "total": 100, "page": 1, "limit": 10, "totalPages": 10 } }
Error
{ "success": false, "message": "Not found", "error": "NOT_FOUND" }
Validation Error
{ "success": false, "message": "Validation failed",
  "errors": [{ "field": "email", "message": "Invalid email" }] }

HTTP Code	Meaning
200	Success
201	Created
400	Bad request / validation error
401	Not authenticated
403	Not authorized (wrong role)
404	Not found
500	Server error

Navigation Flow
•	User visits / → Landing Page
•	Clicks Login → /login
•	On success → fetch role from users table → store in Zustand authStore
•	Redirect by role:
◦	admin → /admin/dashboard
◦	staff → /staff/dashboard
◦	donor → /donor/dashboard
◦	patient → /patient/dashboard
•	Protected routes: no token → /login | wrong role → own dashboard
•	Logout: clear Zustand + Supabase session → /login
•	Signup: only donor/patient can self-register → email verify → login

Zustand State Management
authStore.js
user: { id, name, email, role }
token: string
isAuthenticated: boolean
setUser(user) | clearUser()
Persist: localStorage
inventoryStore.js
inventory: []
lowStockTypes: []   ← blood types below 5 units
fetchInventory()    ← GET /api/inventory
updateStock(id, units)
notificationStore.js
notifications: []
unreadCount: 0
fetchNotifications()  ← GET /api/notifications
markAsRead(id)
Poll every 30 seconds: setInterval(fetchNotifications, 30000)

  Express app with: cors(), express.json(), helmet(), morgan(), dotenv
  Env: SUPABASE_URL, SUPABASE_SERVICE_KEY, PORT=5000

Middleware (apply in this order):
1. cors()
2. express.json()
3. authMiddleware.js:
   Extract JWT from Authorization header
   Verify with Supabase | Attach user to req.user
   Invalid → 401
4. roleMiddleware.js:
   roleMiddleware('admin') or roleMiddleware('admin','staff')
   Wrong role → 403
5. errorHandler.js:
   Catch all errors | Return standard error format

Response format - ALL routes:
  Success: { success:true, message, data }
  Paginated: { success:true, data, pagination:{total,page,limit,totalPages} }
  Error: { success:false, message, error }
  Validation: { success:false, message, errors:[{field,message}] }

Routes:

AUTH /api/auth:
  POST /login → Supabase signInWithPassword
  POST /signup → Supabase signUp + insert to users table
  POST /logout → Supabase signOut
  GET /me → return req.user

DONORS /api/donors [auth required]:
  GET / → paginated, search name/blood_type [admin,staff]
  GET /:id [admin,staff,own donor]
  POST / [admin,staff]
  PUT /:id [admin,staff]
  DELETE /:id [admin only]
  GET /:id/history [admin,staff,own donor]

DONATIONS /api/donations [auth required]:
  GET / filter by status [admin,staff]
  GET /:id [admin,staff]
  POST / record new [staff]
  PUT /:id/test-result [staff]:
    approved → auto insert to blood_inventory
    rejected → create notification for donor

INVENTORY /api/inventory [auth required]:
  GET / filter by blood_type/status [all roles]
  GET /low-stock → types below 5 units [admin,staff]
  POST / add stock [admin,staff]
  PUT /:id [admin]
  DELETE /:id [admin]

REQUESTS /api/requests [auth required]:
  GET / → all [admin,staff] or own [patient]
  GET /:id [admin,staff,own patient]
  POST / [patient]
  PUT /:id/status [admin,staff]:
    approved → deduct from blood_inventory

STAFF /api/staff [admin only]:
  GET / | POST / | PUT /:id | DELETE /:id

NOTIFICATIONS /api/notifications [auth required]:
  GET / → own notifications
  PUT /:id/read | PUT /read-all

REPORTS /api/reports [admin only]:
  GET /monthly → donations grouped by month + year param
  GET /inventory → stock + usage stats
  GET /donors → top donors + inactive list
  GET /expired → expired inventory log
